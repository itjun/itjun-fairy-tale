# 花园王国

根据一位 6 岁小画家的 11 幅作品制作的亲子游戏。Three.js 渲染立体跳台和彩笔纸片角色；城堡、家人、花朵、彩虹与冰淇淋来自原画风格的生成素材。保留原花园互动与全部原画画展。按钮与弹窗使用真实彩笔纸张纹理，中文使用随包提供的霞鹜文楷手写字体，离线可用，字体许可见 `public/fonts/OFL.txt`。

[下载安装最新版](https://github.com/itjun/itjun-fairy-tale/releases/latest) · [问题反馈](https://github.com/itjun/itjun-fairy-tale/issues) · [MIT 许可证](LICENSE)

## macOS / Windows 桌面版

Electron 桌面版启动即全屏，安装后无需 Node 或浏览器，游戏可离线运行；联网时可检查更新。macOS 提供 Apple Silicon / Intel 的 DMG 和 ZIP；Windows 提供 x64 / ARM64 的安装程序。打包产物在 `release/`，不包含家庭 SQLite 数据和测试存档。

- 首页与应用菜单有“全屏 / 窗口”“保存并退出”。F11 切换全屏，macOS 也支持 Control + Command + F；Esc 暂停游戏。
- 关闭窗口、Command + Q 或 Alt + F4 都先保存本局再退出；保存失败会提示留在游戏重试。重复打开只唤起原窗口。
- 成绩存在系统用户数据目录下的 `花园王国/saves/garden.sqlite`：macOS 通常位于 `~/Library/Application Support/`，Windows 通常位于 `%APPDATA%/`。更新应用不覆盖成绩。
- 原生菜单“成绩本”提供备份、导入旧版 SQLite 和打开存档目录。Windows 全屏时按 Alt 可显示菜单，也可先切换窗口。
- 原花园的小成就、贴纸仍保存在应用的本地存储。旧浏览器进度不会自动继承：在网页首页底部“家长工具”导出 JSON，再到桌面版导入；已有成就会合并保留。SQLite 备份仅包含跳台成绩。
- macOS 安装包当前采用本地 ad-hoc 签名，未做 Apple Developer ID 签名和公证；Windows 包未做发布者签名。首次下载时系统可能要求确认开发者来源。Mac 安装后请将应用移到可写的“应用程序”目录，不要在 DMG 中运行；自动更新不会绕过系统首次安装确认。

## 开发与打包

开发环境固定 Node **26.13.0 LTS**（见 `.nvmrc`）。Electron **45.2.3 stable** 自带 Node **24.22.2 LTS**，无需终端用户安装 Node。Electron 没有 LTS 分支，按官方最近三个稳定主版本的支持政策更新；React **19.3.1**、Vite **8.3.5** 等采用当前稳定版并锁入 lockfile。

```sh
npm ci
npm start              # 构建并打开全屏 Electron
npm run build
npm test               # 物理、计分、SQLite、桌面协议、迁移和 Sites
npm run desktop:test   # 独立临时存档：全屏、真实跳跃、关闭保存、重启检查
npm run pack:mac       # macOS Apple Silicon + Intel
npm run pack:win       # Windows 安装包
```

推荐在对应系统打包。跨平台打包成功不等于目标系统真机验收。GitHub Actions 的发布流程与校验见下文。

应用图标源图为 `build/icon-source.png`，由内置 Image Gen 按彩笔城堡风格生成；`npm run icons` 可重建 ICNS / ICO / PNG 及网页图标，完整提示词见 `docs/asset-prompts-desktop.md`。

## 保留的网页版本

```sh
npm run dev            # 网页开发服务
npm run build
npm run play -- --open # 本机浏览器版本
```

网页版默认只监听 `127.0.0.1:4173`，SQLite 仍位于项目 `data/garden.sqlite`；开发模式首次打开 Electron 时会快照复制此数据库到桌面存档目录，原文件不修改。打包版从“成绩本 → 导入成绩本”导入旧库。

桌面版使用固定 `garden://app` 地址，直接在应用内处理 `/api/`，无需监听 HTTP 端口。渲染进程使用隔离上下文和沙箱，外部网络默认禁用。保留的 Sites worker 不提供 SQLite 接口；原 Sites 文件结构保持完整。

## 关卡与操作

首页点“去跳台探险”，选择关卡和单人 / 双人模式。0.3.0 的新局使用版本化随机地图：主题固定，区域组合、支路、平台、宝物种类位置和小怪巡逻按种子变化。后续关卡的主线区域及内容规模逐级增加。

| 关卡 | 主要结构与机制 | 必经区域数 | 通关奖励 |
| --- | --- | --- | --- |
| 彩虹花园 | 花田缓坡、拱桥、彩虹山丘 | 3 | 50 分 |
| 家人小镇 | 街巷、遮阳棚与屋顶 | 4 | 80 分 |
| 甜甜城堡 | 传送带、星星开桥、地窖弹簧 | 5 | 100 分 |
| 贝壳海边 | 踏石、横移木筏、岛屿栈桥 | 6 | 80 分 |
| 风车草地 | 山谷、风车升降、弹跳花坡 | 7 | 70 分 |
| 雪人乐园 | 缓滑冰面、雪洞、横移冰台 | 8 | 90 分 |
| 蘑菇森林 | 树根洞、折返攀登、叶台、树冠桥 | 9 | 90 分 |
| 卡通梦工场 | 积木、传送带、齿轮、气球和火箭塔路线 | 10 | 100 分 |

每局 HUD 显示实际宝物目标；目标由该种子的主路宝物数量决定，不依赖随机掉落。经过每个区域的恢复旗、拿够宝物并到终点才通关。通关只需点一次“去下一关”，直接开始并保留单双人模式。

| 玩家 | 移动 | 跳跃 | 攻击 |
| --- | --- | --- | --- |
| 小女孩（单人） | A / D 或 ← / → | 空格、W 或 ↑ | J |
| 小女孩（双人） | A / D | 空格或 W | J |
| 爸爸（双人） | ← / → | ↑ | Enter |

按住攻击键连续发射，也能在空中攻击。触屏的攻击按钮显示当前技能名称；双人需要键盘。下方向加跳跃可穿过单向平台。

- **贯穿光刃**：默认技能，每 0.4 秒发射一次，穿过平台和沿途小怪，飞到发射时前方屏幕边缘后消失。同一光刃对同一只怪只命中一次。
- **魔法泡泡**：每 0.65 秒发射一颗泡泡，碰到怪物后炸开彩笔星光，攻击周围的小怪。
- **彩虹星雨**：每 0.55 秒发射五颗扇形星弹，覆盖前方高低路线，带星光拖尾。
- 每个区域沿主线随机放两份技能奖励，两个强化种类交替出现，起始种类由种子决定。捡到后自动替换当前强化，持续 **32 秒**，双人一起生效；再次拾取另一份奖励重新计时，到时恢复光刃。获得时有彩笔光环、星星散开、提示与音效，不增加选技能菜单。暂停不消耗，掉落保留，下一关重新寻找奖励。

- 果冻、叶子、飞行绒球的击败基础分分别为 **10 / 15 / 20**。部分小怪确定性掉落主题宝物，直接收取；踩头与技能攻击同样奖励。后期带两颗星的小怪需要两次命中。
- 宝物分值：小花 10、蘑菇 15、贝壳 20、爱心 25、雪花 30、气球 35、星星 40、冰淇淋 45、彩虹 50。结算分开显示宝物、打怪和通关奖励。
- 无限生命、掉落不扣分。侧碰提供短暂保护；恢复时保留已收集宝物、已击败小怪和打开的机关。双人共享奖励，同一编号只计一次。
- 暂停菜单仅保留“继续探险”和“回到我的花园”。首页可继续上次冒险，或选择“新冒险”后重新选关。成绩本、全屏、退出和更新入口留在首页或应用菜单。
- 关闭后在最近安全台续关；地图种子、已拿奖励、小怪剩余生命、巡逻状态、机关、技能剩余时间与游玩时长保存在当前应用本地存储。恢复时清空在途攻击和按键。清理应用本地存储会丢失续关状态；SQLite 成绩备份不包含这份续关状态。
- 新局使用计分版本 3 / 生成版本 1。服务端从种子重建奖励清单、合并已拾取及已击败编号，不信任上报总分。历史计分版本 1 / 2 保持原规则，旧成绩不重算。

设计与验收范围见 `docs/design/level-expansion/README.md` 和 `design-qa.md`。自动路线模拟约从 2 分钟递增至 9 分钟；这不是儿童真人试玩时长保证，实际用时受探索、战斗与掉落次数影响。

## 成绩本与 SQLite

首页和应用菜单可以打开“我的成绩本”。每次点击出发进入一关，创建一条记录；暂停、继续、保存重试不会增加次数。中途结束和 0 分游玩也会记录。

- 汇总包含累计分数、次数、最高分、平均分、通关数与游玩时长。
- 支持今天、近 7 天、近 30 天、全部和自定义日期，也可按关卡筛选。
- 曲线按真实游玩开始时间排列，不同颜色代表不同关卡；可切换每日平均。没玩的日期不补零。
- 每日平均按当前电脑时区、各关卡分别计算；超过 1,000 次记录自动用每日平均，明细每页 20 条。
- 汇总与曲线包含进行中、暂停和已结束的记录。未正常退出的记录超过一分钟未更新显示“中途离开”，已经保存的分数仍保留。

收集宝物、击败小怪和经过区域旗子时立即保存，并每 3 秒保存一次时长；暂停、通关、结束和离开时再次保存。只有服务确认写库，界面才显示“积分已保存到这台电脑”。服务断开时会暂存到当前浏览器，保留页面可重试，重新打开游戏也会补存。异常断电仍可能丢失尚未写入或尚未暂存的最后几秒；清理浏览器数据会删除尚未补存的队列。

网页版默认数据库是项目下的 **`data/garden.sqlite`**，首次启动自动创建。SQLite 使用 WAL，运行时可能有 `garden.sqlite-wal` 和 `garden.sqlite-shm`。**备份前先关闭游戏服务，然后复制整个 `data/` 目录。** 升级程序时保留此目录；换电脑时也一起迁移。旧版本没有记录积分，过去的游玩无法追溯。安装包不附带测试成绩。

## 原花园玩法

找回彩虹、照顾花朵、给一家人分享冰淇淋，完成后开派对；还可以贴纸、撤回、保存花园照片、浏览 11 幅原画。原花园成就存于当前浏览器，与 SQLite 探险成绩分开保存。语音依赖系统中文声音，没有语音仍可玩。

## 开发与验证

```sh
npm ci
npm run dev -- --port 4173
npm test
npm run build
```

- `src/game/`：Three.js 场景、键盘 / 触屏、碰撞、随机平台与结算。
- `shared/levels.js`：主题信息与旧版本计分；`shared/campaign.js`：版本化随机地图和新奖励清单。
- `src/scores/`：本地待保存队列、成绩查询、Chart.js 曲线。
- `server/`：Node HTTP 服务与内置 `node:sqlite`，无需额外数据库安装。
- `data/`：正式成绩；可用环境变量 `GARDEN_DB_PATH` 指定隔离测试库。
- `public/assets/`：参考原画生成的 PNG；`public/artworks/`：原画浏览副本，原始附件未修改。
- `tests/`：平台可达性、SQLite 持久化与统计、接口、保存队列、原 Sites runtime 测试。

原有 `.openai/hosting.json`、`worker/` 和构建脚本保留。`npm run build` 输出 `dist/client` 及 Sites 兼容文件；家庭电脑实际使用 `server/index.mjs` 提供页面和 SQLite API。所有运行资源随包交付，无远程 CDN。

已在本机浏览器验证真实通关、积分写入、关卡切换、统计筛选、断开服务后补存。Windows 真机、长时间运行和手机实体多点触控尚未实测。详细证据见 `design-qa.md`。

## 一键本机构建与启动

安装 `.nvmrc` 指定的 Node LTS 和 Python 3 后，在仓库根目录执行：

```sh
python build.py
# macOS 如果命令名是 python3：
python3 build.py
# 只构建安装，不启动：
python3 build.py --no-launch
```

脚本先让本游戏旧进程保存退出，等待 15 秒后仅强制结束仍存活的项目进程，再执行 `npm ci`、构建、测试、按本机架构打包并安装。macOS 安装到可写的 `/Applications`，否则使用 `~/Applications`；Windows 使用当前用户的 `%LOCALAPPDATA%/Programs/GardenKingdom`。成功后启动全屏游戏。macOS 成功安装后同时生成 ZIP，将旧程序和构建副本移到废纸篓并取消其应用登记，只保留正式安装入口。用户数据目录不会被覆盖。Node 版本不匹配时会提前停止，不修改全局 Node。

## 发布新版与自动更新

维护者修改 `package.json` / lockfile 的版本号和 `docs/release-notes.md` 后，提交并推送对应标签：

```sh
npm version patch
git push origin main --follow-tags
```

`.github/workflows/desktop.yml` 为 macOS / Windows 的 ARM64、x64 分别构建。全部成功后生成 `garden-update.json`（架构、文件大小、SHA-512）和 `SHA256SUMS.txt`，先上传到草稿 Release，资产齐全后公开为最新版。普通分支 push 不发布；手动运行只上传构建产物。版本标签必须与 package 版本一致，失败的任务不会发布不完整的新版。

应用启动 12 秒后及每 4 小时检查 GitHub 最新正式版本，也可以点“检查更新”。新版自动下载；进入首页或暂停/结算界面后等待 5 秒，自动保存当前成绩、安装、重启全屏。正在跳跃时不会自动重启；暂停局会结束并保存，更新后重新选关。断网、校验失败或保存失败均保留现有应用和存档，可以稍后重试。

如果使用过 0.1.0 / 0.1.1 早期预览包，请手动安装 0.1.2 或更新版本一次，修复 macOS 中文 ZIP 校验问题；个人存档保留。后续正式版本使用上述自动更新流程。

更新器只接受本仓库的稳定版本，拒绝降级、错误架构与哈希不匹配的包。Windows 使用当前用户 NSIS 静默安装；Mac 校验应用标识、版本、架构及 ad-hoc 签名后，在原应用目录暂存、退出后原子替换并保留 `.previous` 回退副本。当前不使用需要 Developer ID 的 Squirrel.Mac；SHA-512 校验依赖 GitHub 发布账户和 HTTPS 的可信性，不能替代发布者签名。Mac 原位置不可写或位于磁盘映像时会提示迁移目录。更新失败信息在界面显示；存档独立于安装位置。
