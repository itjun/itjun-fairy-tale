2026-11-11，按用户已确认方案实现。视觉依据为同目录的 `rainbow.png`、`garden.png`、`treat.png`。三张分别对应三款游戏，不是备选方案；图中为中段示例，实际内容按完整三阶段展开。

| --- | --- | --- |

所有随机任务都有已知解。小雨/晴天仅满足当前对应需求，同一天气只能使用一次；不靠真实时间推进。错放保留盘面并给反馈，排列和制作可撤回。双订单可自由切换，送出后的订单不能撤回或重复结算。

## 代码与存储

`src/mini-games/` 分开任务生成、状态机、三款界面、共享交互和场景外壳。点击与拖拽进入同一状态规则；任务 ID 和版本拒绝旧事件。状态含随机种子、完整任务、阶段索引、完成记录、操作盘面、撤回历史及提示级别。有效操作同步写入既有花园 localStorage。

成就和当前随机局分开。完成后重玩只新建对应局，旧成就和贴纸保留。读档校验任务及盘面，拒绝损坏或无法继续的局。花园备份版本 2，继续接收版本 1；本机已有随机局优先，不拼不同局。

背景、机关、拼图片、种苗、花苞、水壶、太阳、蝴蝶和冰淇淋材料使用真实 PNG；原画女孩、家庭、粉花、爱心和星星直接复用。文本使用项目本地 GardenHand，按钮沿用项目手绘纹理。声音可关闭；开启时有操作音和阶段/提示朗读，声音不阻塞操作。

## 校准与验证

内容设计目标每款 8～12 分钟。程序的最短正确操作数约为彩虹 44 次、花朵 48 次（天气可减少）、甜蜜分享 62 次；每次放置可用一次拖拽或两次点击。实际还包含观察、推理、选择、检查和调整，不能把自动化输入时长换算成儿童用时。

浏览器已逐款完整走通并重玩；覆盖机关撤回后刷新、照料中途刷新、双订单交替制作后刷新。390×844 窄窗口验证点击与实际指针拖拽；桌面比较三张参考稿与实际截图。未进行真实儿童计时和 Windows 实机测试，8～12 分钟不是已测得承诺；后续应记录每阶段观察时间、错误/提示次数，再调整模板复杂度，不增加强制等待。

自动化覆盖每款 80 个随机种子的可解性、每步保存恢复、阶段推进、防重、提示、撤回、天气、双订单、重玩、旧成就和两版备份。桌面烟雾测试通过界面为三个小游戏各做一步，关闭并重开后比对盘面，同时验证原跳台成绩与全屏恢复。

界面截图和逐轮修正记录见仓库根目录 `design-qa.md`；`docs/qa/` 为本地测试产物，不打包。

## 语音反馈调整

用户反馈系统朗读过于机械，现改为预生成普通话女声；将标题播报改成陪伴式短句。阶段开场、两级提示和结算使用同一音色，只在阶段切换或主动点提示时播放；同阶段下一道题不会反复插话。关闭声音或回花园立即停止，不混播、不使用系统机械声音兜底。

音频位于 `public/audio/guidance/`，离线播放。更新文案后运行 `node scripts/prepare-voice-lines.mjs`，再用安装了 `edge-tts==7.3.1` 的独立 Python 环境运行 `scripts/generate-guidance-audio.py`。普通构建不会连接语音服务。文案、音色和语速保存在 manifest 中，便于以后替换为真人录音。
