# 八关独立地图与递增流程提案

2026-11-09。状态：用户认可代表设计稿的画风与方向，并补充要求类似肉鸽的随机地图、物品奖励和小怪布局，以及主角远程攻击、击败怪物获得奖励。本文已据此修订；新增光波攻击效果稿待确认。关卡生成、攻击、物理和计分尚未实现本次扩展。直接下一关与菜单精简继续保留。

## 问题依据

当前 `shared/levels.js` 的八关共用 stairs、cave、canopy 三种路线。`src/game/world.js` 的主结构固定，随机性主要是台阶的小幅偏移、宽度和敌人初始位置；终点 x 分别为 42、43、50。每关固定三只小怪。配置中的 platforms 实际用于宝物数量与进度，不是整个地图的长度。因此只增加这个数字不会产生更丰富的地图。

## 已确认要求与本次建议

用户要求：每关的地图不一样，流程更丰富，每关主线比前一关更长；每次新局的地图、物品奖励和小怪布局都随机，类似肉鸽游戏。保留彩笔原画、八关原名称、无限生命、温柔恢复、单人及双人模式、直接下一关和精简按钮。

本次建议：第一关目标约 2 分钟，此后每关增加约 1 分钟，最后约 9 分钟。这是熟悉移动与跳跃后、正常探索主线的设计目标，不是计时限制，也不是已测得的结果。玩家熟练程度会影响实际时间；开发后用同一批试玩者的各关中位完成时间校准递增关系。支线用时不计入主线目标。

## 八关路线

每关固定自己的主题、特色机关和生成规则，主线骨架也参与随机：区域的选取、兼容区域的顺序、连接方式、上下路线和支线位置都可以变化。先生成可达的路线，再放奖励和小怪，最后生成装饰。不得只微调平台位置，也不得把三张代表稿变成八关重复套用的新模板。

## 类肉鸽的随机生成规则

### 每次新局会变化什么

| 层次 | 每局随机内容 | 保持的约束 |
| --- | --- | --- |
| 地图结构 | 区域选择与组合、兼容段落顺序、分岔与汇合位置、上下路线、桥洞与升降连接、支线入口 | 关卡主题和独有机制明确；主线全部可达，无底层直通捷径、无强制无意义折返 |
| 地形细节 | 台阶高度与跨度、洞穴入口、岛屿宽度、平台运动相位及安全停靠位置 | 跳跃物理可达，单人能通关；双人会合与恢复点可用 |
| 物品奖励 | 各主题宝物池中的物品种类、位置、组合；支线与机关后的高分奖励 | 分值沿用已定义规则，界面展示明确；主线有足够宝物，额外奖励放在可选探索处 |
| 小怪 | 可用种类、分段数量、巡逻台面、方向与速度范围、局部遭遇组合 | 出生区和恢复点留空；安全落台不被完全封住；普通遭遇 1 只，后期局部最多 2 只 |
| 背景与装饰 | 原画元素的组合、位置、前后景细节 | 同主题仍能一眼认出；装饰与可站立的平台清晰区分 |

例：贝壳海边的新局 A 可以从踏石抵达木筏，再登沙堡，经高桥到灯塔；新局 B 可以先穿礁石洞，从洞顶登岛，再乘木筏跨湾，经低栈桥到灯塔。不同连接和分岔对应不同奖励及怪物布局，仍保留海边的岛屿与移动木筏特色。

### 奖励与通关

- 首期随机奖励围绕现有爱心、星星、彩虹、冰淇淋、贝壳、蘑菇等收集物展开；物品种类和组合随机，不把同一物品的分值偷偷改变。
- 用关卡和区域的奖励额度控制总体分值范围。更长的后期关卡提供更多奖励机会；额外支线与稍难路线放高分宝物。
- 在生成阶段保证主线宝物总量满足通关需求，剩余目标始终可完成。通关不能依赖某个随机概率掉落物，更不能因运气差被卡住。
- 同一宝物只有一个稳定编号，双人重复触碰只计一次；掉落恢复不会让已收集奖励重新出现。
- 主角远程攻击和击败奖励已纳入本次范围，详见下文。装备构筑、技能树和跨局成长仍属于独立后续功能，不额外增加选择菜单。

## 主角远程攻击与击败奖励

用户已要求增加光波或飞刀攻击，并给予击败奖励。当前提案先采用光波，飞刀是用户允许的另一种方向，不代表两种武器均已确定实现。本次实现采用下列按键、参数和分值；后续按真人试玩反馈校准。

### 人物与画面

- 保留原粉裙小女孩的发型、笑脸、黑色彩笔轮廓和三角裙，不换成另一套人物。补充朝左/朝右、走路、跳跃、抬手发射和轻碰保护动作，爸爸采用同一画风与攻击能力。
- 光波为青蓝与粉色的短弧形彩笔笔触，从抬起的手掌向人物朝向飞出。起跳时也可发射，够到不同高度的小怪。
- 命中时小怪短暂闪亮，击败后化成彩色星点和一小团云；显示加分飘字，总分同步变化。用短促柔和音效区分发射、命中、奖励，遵守静音和减少动态效果偏好。
- [光波效果稿](combat-lightwave.png)由内置 ImageGen 生成，参考原 `girl-player.png`、`enemy-jelly.png` 和现有游戏截图。它是效果示意，不是已实现的游戏截图。完整生成提示词保存于 [combat-prompt.txt](combat-prompt.txt)。

### 简单操作

- 小女孩用 J 发射，双人模式爸爸用 Enter 发射；触屏在跳跃旁只增加一个攻击按钮。现有移动、跳跃和下跳继续使用。
- 按住可按固定间隔连续发射，建议初值 0.4 秒；不用反复猛按。无弹药消耗、换弹或武器选择弹窗。
- 只有游玩状态接受攻击输入；暂停、切关、失焦和退出时清空按住状态及在途光波，避免下一关或菜单中意外开火。
- 最初的普通小怪一击可打败；后期较强变体可需两击并有明显外观与受击反馈。具体强度按主题、区域和后期难度额度生成，不能随机出现无法应对的组合。
- 光波有有限射程，遇到实心墙、地面或目标停止；不能隔着整座地图清怪。单向平台的阻挡规则应统一并通过试玩确定。跳跃避怪与踩头仍然有效。

### 击败奖励

建议基本奖励：果冻怪 10 分、叶子怪 15 分、飞行云朵怪 20 分。每次击败必得基本分，光波与踩头使用同一奖励规则；掉进地图边界、清理屏幕外对象等不能算玩家击败。

部分小怪额外掉落主题宝物，例如海边的贝壳、森林的蘑菇、城堡的冰淇淋。是否掉落及物品种类由本局种子和怪物编号确定，自动飘向角色收取，不让奖励落进深坑。额外物品沿用已有分值，基础击败分与掉落分合并提示或分次清楚展示，不把示意图中的爱心误当作固定 10 分。

- 普通怪的必得分让攻击有明确回报；额外掉落带来随机惊喜。总体掉落额度随区域安排，不能让早期刷怪收益压过后期探索。
- 每只怪有本局唯一编号。双人同时命中、光波与踩头同帧命中、连续碰撞只结算一次，团队共享奖励。
- 掉落恢复、暂停及恢复同一局不会复活已击败小怪，也不会重抽掉落；重开新局才重新生成。
- 击败奖励独立于关卡必需宝物目标，通关不强制清场，也不依赖概率掉落。高处和支线仍有值得跳跃探索的宝物。
- 结算在原有分数明细中显示宝物分、打怪分及通关奖励，不新增按钮或一层弹窗；额外掉落归入宝物分，不能与打怪分重复计算。

### 计分与验证

新局保存生成版本、奖励规则版本与已击败怪物编号。服务端按同一版本和种子解析怪物基础分、确定性掉落，并与已拾取宝物合并去重；不可直接信任客户端上报的总分。历史局继续用原有计分规则，不能因加入打怪奖励改写旧成绩。

新增验证覆盖：左右发射、空中命中、射程和遮挡、高速光波不穿过怪物、按住发射频率、暂停清空输入、双人同时击败只计一次、同局恢复不刷怪、网络重试不重复加分、旧成绩兼容以及单人和双人的菜单键盘操作不误触攻击。

### 随机与递增时长如何兼容

- 每关的必经段数、有效路线长度、机关使用次数和遭遇安排具有分级内容额度，后一关的主线内容额度高于前一关；随机只在相应级别内组合。
- 不允许随机抽成很短的直通地图。长路线也不能通过延长等待、重复低价值路段来达到目标。
- 同一关连续新局避免重复同一套布局签名，同时不依赖非确定性重抽破坏存档复现。
- 内容规模递增可由生成器验证，但实际通关时间不能对每一次游玩作严格递增保证；熟练度、走法和掉落次数仍会影响用时。仍按各关正常主线试玩的中位时间校准 2～9 分钟目标。

### 何时重新生成

- 从花园开启新冒险、通关进入下一关、最后一关后再开第一关：生成新种子。
- 同一局暂停、恢复、掉落、回安全台、双人会合：保留种子、地图、怪物状态、机关状态及已拿奖励。
- 保存后恢复同一局必须恢复原种子和进度。不要把“历史成绩能读取”误当成已有“中途续关”能力；若增加中途续关，需要另存完整局内状态并验证。
- 种子连同地图生成版本、奖励规则版本持久化；同一版本同一种子产生一致的地图、奖励和小怪，便于恢复及排查。
- 使用分别派生的地形、奖励、小怪、装饰随机流，新增一朵背景花不应改变当前种子的地图或积分。

### 生成与回退

生成候选结构 → 校验连接、动作和机关依赖 → 放奖励与敌人 → 校验奖励可达及安全落点 → 验证内容额度。候选不通过时限次重新生成；超过上限采用该关同级、已验证的备用组合。备用组合仍满足该关内容规模，不回退到旧短图。

种子、备用分支选择及生成版本共同决定最终结果；客户端渲染和服务端计分必须使用同一确定性奖励规则。旧局继续使用旧规则与原始分数。

### 每关的节奏约束

- 每段都有明确的新地形或动作变化，不能靠重复平台、长空路、拖慢移动速度、长时间等电梯或提高收集门槛凑时长。
- 后续关卡增加段落和组合，不突然缩小落脚点、加快全部小怪或增加惩罚。
- 小怪按场景布置：地面巡逻、桥面转向、高处飞行；单次遭遇通常 1 只，后期局部最多 2 只。数量随内容增加，不堆满画面。
- 每段入口或关键机关后设置恢复点；掉落只回当前段的安全位置，保留已收集宝物和已打开的机关。
- 每关可有一条短支线，奖励额外宝物后接回主路。主线的全部段落必须真正经过，不能沿平坦底层直接跑到终点。
- 有机关的段落先在安全处展示，再让玩家使用，最后与小怪或另一种平台组合。保持现有移动、跳跃、下跳操作；踏板自动触发，不新增操作面板。
- 双人共享机关进度，任何一位玩家触发即可；恢复点和会合位置必须是安全静态地面，不把另一人传送进深坑或移动平台底下。
- 不增加关卡内强制弹窗或章节确认。通关后仍只需点一次“去下一关”。

## 开发及验收要点（确认设计后执行）

1. 地图按关卡建立独立的区域库和连接规则，通用模块负责平台、升降、传送带、恢复点等基础能力。区域库需要足够多结构变体，避免有限模板很快重复。按相同种子复现全部玩法布局。
2. 路线包含下潜、回绕和竖向段落后，进度不能继续只按 x 坐标计算。用必经区域与机关完成情况决定进度，避免越过区域、提前通关或进度倒退。
3. 宝物数量增加前先拆清地图规模、宝物编号与历史计分规则。旧局保存原规则和分数，新局使用版本化规则；不可把旧局用新的宝物数量或通关门槛重新解释。
4. 每关至少覆盖 200 个种子的结构与奖励约束检查，并对选定种子进行物理寻路和实际试玩。验证主线、支线、每个恢复点和移动平台衔接，确保没有软锁；检查生成超时、限次回退、布局多样性及各级内容额度。机关开启后不因落水或双人会合重置。
5. 对长地图只更新和绘制必要区域，验证家庭电脑的帧率与内存；地图扩充不应把全部小怪与特效持续放进同一画面。
