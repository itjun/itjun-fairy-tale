## 人物辨识依据

- 爸爸：四格白色方形上衣、短发、细长四肢。
- 妈妈：较高的红色三角裙人物，顶部发髻和两侧长发。
- 姐姐：较高的小女孩、两侧发束、粉红三角裙。
- 妹妹：最小的小女孩、明显的高椭圆发髻、短三角裙。

以上按第 7 幅原画中的体型和站位对应；保留原画不规则粗黑线和留白笔触。正式人物素材需从原画身份延展站立、跳跃、攻击姿势，不把四个人都替换成同一个旧 girl-player。

## 已确认并实现的共同玩法

- 已确认使用爸爸、妈妈、姐姐、妹妹四位原画风格人物；每次新冒险选一位，跨关保持，途中不能靠切换角色重置天赋或生命。
- 姐姐：星雨连击。四次有效发射累计后，追加一次向前星雨。按住攻击仍按真实发射次数累计，不能靠重复按键空刷。角色天赋独立于装备的主武器，不把现有星雨武器占为专属。
- 爸爸：彩虹护盾。抵挡一次怪物接触或弹丸伤害，消耗后冷却恢复；冷却 20 秒有效游玩时间，暂停不推进。不能抵挡掉坑，不能靠开关菜单刷新。
- 妈妈：花朵缠绕。每第四次有效发射在首个命中点开花，短暂减慢周围小怪；减速 2 秒，不附加无限回血或补命。
- 妹妹：轻盈二段跳。每次腾空期间可再按一次原跳跃键起跳，落地恢复次数；按住不自动连跳，手动下跳不重置次数。所有主线仍可用其他角色的基础跳跃完成。
- 攻击与护盾天赋自动触发，妹妹复用跳跃键，移动、跳跃、攻击键保持一致；所有角色仍可收集现有六种武器和十八项强化。角色天赋不占三个强化槽位。
- 每次新冒险体力 3 格、生命 9 条。普通怪物/弹丸命中扣 1 格体力，并给短暂无敌，防止重叠命中同帧连扣。
- 体力归零或掉坑均算死亡，一次死亡只扣一条命。尚有命时恢复到本段检查点、补满体力，保留地图、已领奖励和技能；命归零时结束本次冒险。
- 命归零后的新冒险重新选角色和构筑；保留历史积分、花园成就和贴纸。不是死亡就扣掉历史分数。
- 初版不设计无限回血/补命的休息点；是否通关补命留待试玩校准，不在实现中悄悄加入。恢复满体力发生在扣命后的复活，不发生在普通刷新、回花园或手动回安全台。
- 暂停、退出、刷新保存并恢复命数、体力、冷却、攻击累计及死亡状态；死亡扣命需先持久化，不允许退出重开撤销惩罚。

## 界面和存档边界

- 状态栏分别标明“体力”和“生命”，不可再显示无限生命；命数与体力不用同一排无标签爱心混淆。图中示意图标并非最终固定编码。
- 有命的死亡提示显示剩余命数和“回检查点”；零命结算只保留“新冒险”“回花园”。通关仍直接下一关，继承当前角色与本次构筑。
- 旧双人存档需明确迁移到单人：保存原数据备份，不能删除家庭历史；旧积分记录中的双人标签是历史事实，可保留。旧局统一转为姐姐并保留第一位装备，共享背包完整保留；首次新格式保存前将旧数据写入独立备份键，不继续提供协同游玩入口。
- 三个独立小游戏不受本次生命规则影响。

## 开发验收要点

单人所有入口与按键、四角色真实差异、二段跳次数与落地恢复、每次发射累计、护盾冷却与暂停、同时碰怪与掉坑只扣一次、零命不能续关、扣命保存与重开、跨关保持角色/技能、旧存档迁移与旧分数保持、窄屏生命显示和选角可访问性。最终需运行浏览器和隔离桌面存档验证。

四人营地、技能、生命机制已实现；实机验收记录见根目录 `design-qa.md`。本次只在本机构建安装，不提交、推送或发布。

## 素材与实现

- 爸爸沿用原 `dad-player` / `dad-attack`，保留四格白衣。
- `mom-player` / `mom-attack`、`sister-player` / `sister-attack`、`little-player` / `little-attack` 均以第 7 幅原画身份和已选营地稿为依据，用 Image Gen 分别生成真实透明 PNG，保留白色脸部。跳跃通过各自站立素材随物理运动表现。
- `character-camp.png` 为独立生成的无角色营地背景；“出发营地”是画中布旗，其他文字、角色选择、技能计数与按钮均为真实界面。
- 试用区使用同一跳跃、发射、命中和天赋逻辑，不修改正式局的生命或积分。所有角色沿用原有六种武器与十八项升级。
- `characters.js` 管理天赋和生命状态；`engine.js` 单人运行并在扣命时暂停及立即保存；`save.js` 验证和兼容旧存档。
